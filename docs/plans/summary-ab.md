# 주제별 AI 정리 A/B 선택

같은 녹음의 전사와 분류 목록으로 주제별 문서 묶음 두 개를 만든다. A는 현재 `topic-analysis-v4` 프롬프트를 유지하고, B는 핵심 요약 뒤에 회의에 존재하는 결정·보류·미결정·할 일을 이 순서로 둔다. 이후 필요한 맥락 섹션을 이어 쓴다.

- 회의마다 첫 번째 후보를 무작위로 정하고 로컬 DB에 보존한다. 화면에는 `정리 1`, `정리 2`만 표시한다.
- 결과 두 개와 원시 응답을 모두 불변 artifact로 서버 DB에 보관한다. 선택 전에는 후보를 문서 목록에 넣거나 발행하지 않는다.
- 사용자는 후보 하나, 이유 하나(결정·할 일이 더 잘 보여 / 내용이 더 정확해 / 더 읽기 편해 / 기타), 회의 종류 하나(여러 안건 회의 / 인터뷰·피드백 / 소개·공유)를 선택한다. 기타에는 선택적인 설명을 500자까지 입력할 수 있다.
- 선택과 발행 대기 작업을 로컬 트랜잭션으로 함께 저장한다. 서버는 선택한 분석, 두 후보와 전사 참조를 검증하고 선택 기록과 문서 발행을 같은 트랜잭션으로 확정한다. 같은 선택의 재전송은 멱등이며 다른 선택으로 바꾸는 요청은 충돌이다.
- 후보 배치와 선택한 A/B, 선택 이유, 회의 종류, 두 분석 ID를 기록한다. 선택받지 못한 후보는 삭제하거나 문서로 발행하지 않는다.
- 두 후보가 준비된 뒤 선택을 받는다. 한쪽 실패 시 완료한 후보를 재사용하고 실패한 쪽만 재시도한다. 전사·분류 입력 스냅샷을 고정하며 모델 설정이 바뀌어 비교 조건이 달라지면 원래 설정으로 재시도하도록 안내한다.
- 과거 발행 문서는 유지한다. 새 녹음부터 비교 흐름을 적용하며 기존 문서 재정리·분류 기능은 유지한다. 선택 변경, 분석 대시보드, 배포·릴리스는 이번 범위에 포함하지 않는다.

계약: `ai_comparison` artifact는 `{schemaVersion:1, transcriptArtifactId, candidates:{A,B}, firstVariant}`를 저장한다. publish의 `selection`은 `{comparisonArtifactId, selectedVariant, reason, meetingType, otherReason?}`다. 로컬 `prototype_summary_comparisons`는 생성 입력과 진행 상태를, 서버 `recording_summary_preferences`는 발행과 연결된 선택을 보관한다.

검증은 선택 전 발행 금지, 두 후보 보존, 입력 일치, 실패·재시작 복구, 좌우 유지, 입력 필수, 선택 후보만 문서 목록 표시, 재전송·소유권·서버 트랜잭션을 확인한다. 실제 AI의 의미 정확성과 사용자 선호는 실험으로 평가한다.

2026-10-06 검증 결과: workspace 테스트 766개와 별도 PostgreSQL 통합 테스트 12개, lint, diff 검사를 통과했다. 합성 전사로 비교 화면의 두 열과 필수 입력 후 발행 버튼 활성화를 확인했다. 기존 사용자 변경 파일 `meetingSummary.ts`의 타입 오류는 보존했다. 이 파일만 HEAD로 대체한 별도 소스 복사본에서는 이번 변경 전체의 타입 검사와 앱 빌드가 통과했다. 실제 녹음·AI 생성, 설치 앱 갱신, 배포는 수행하지 않았다.
